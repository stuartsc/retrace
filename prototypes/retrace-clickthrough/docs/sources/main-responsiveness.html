## Implemented first slice
 
- App-owned automatic processing governor: five-minute input-inactivity hint, one expensive automatic permit, native background scheduler deferral, thermal/load/memory pressure, two Whisper threads in Low Power Mode and four otherwise. Low Power Mode alone does not prohibit catch-up. Global power settings are unchanged.
- Whisper's native encoder/abort callbacks read an owned synchronized cancellation token. Caller cancellation and renewed interaction reject unfinished output. Explicit dictation retains the direct service.
- Durable first-pass audio scheduling and startup recovery are independent of optional exhaustive refinement. V31 adds a partial pending-row index; scheduling uses 16-row keyset pages, three-speech/one-silence priority within each page and a joined 30-second retry timer. Capture activity hints are not a reason to delete or skip audio. Successful raw persistence uses SQLite pending records rather than an unbounded metadata queue. Original-source-guarded first-pass publication and placeholder retirement form one transaction.
- Manual refinement owns a coalesced cancellable task, joins the automatic loop before taking its managers, and uses scoped explicit admission without changing Process now. Recording pause and shutdown join both owners before service teardown; paused historical repair remains available. The recording-session pass-1 guard no longer blocks governed refinement.
- Optional semantic background pages share admission before taking a claim. Explicit queries retain foreground priority. Optional topic generation uses nonblocking admission so deterministic source cards remain responsive.
- Failed persistence stops the audio source and retains one completed failed batch for an explicit recording restart; a successfully written AAC file is reused if only its SQLite insertion failed. Missing persistence dependencies follow the same path. This bounded in-memory failure slot does not provide power-loss recovery for a file that could not be durably registered; no such claim is made.
- System Monitor separates recording, preparation and indexing, with a cancellable in-memory Process now override and categorical metrics. Original spool pressure remains visible; the 5 GiB ceiling/20 GiB headroom and no-eviction rule are unchanged.
- HEVC reporting separates hardware availability, requested selection and unverified actual use. Explicit selection uses the supported top-level encoder specification; the default remains automatic.
- A developer-only authored WAV comparison hashes its model/input and compares CPU/Metal request configurations, words, spans, elapsed time, process CPU and cumulative peak RSS. Core ML/Speech, helper memory and whole-system energy remain separate; there is no production backend promotion.
- An authored AAC comparison queries native applicable bitrates, then measures decoded frames, media timing, retained bytes, encode/decode duration and unaligned PCM SNR. It also attempts native Opus in CAF and records explicit timing/decode failures. Separate authored-clip transcription runs compare every emitted codec candidate; none establishes listening-quality or representative transcription-accuracy acceptance.
- Original spool V3 candidate independently compresses each pixel record using native LZFSE or experimental LZ4, checks bounded decode and exact pixel hashes, and falls back to raw bytes. Existing V1/V2 reads remain compatible. Production writes remain V2; this is not codec promotion.
 
Current low-rate OCR intentionally retains its existing single-worker schedule. Gating historical OCR after dequeue would otherwise hold the only worker while fresh frames arrive; reducing current OCR awaits verified retention and a queue-admission change. An unused historicalOCR permit kind is a future integration contract, not proof of admission in production.

## Exact audio source candidate, September 28 continuation
 
The independently switchable `chunkedAudioCaptureCandidateEnabled` setting applies to new recordings after restart and defaults to false. It encodes each fixed 16 kHz mono Int16 input sample once in at-most-ten-second AAC chunks. Logical windows combine the previous chunk's last five seconds with the new chunk; the manifest contains ordered integer sample ranges, original stream time, exact source/store identity, original/encoded hashes, an initial decoded-hash diagnostic, native AAC valid/priming/remainder frames and track timing. No overlapping encoded file is created. Foundation reference-epoch dates preserve the manifest's original precision through SQLite.
 
New chunk descriptors explicitly carry `decodeContract: nativeAACPCM16V1`. Read admission verifies encoded bytes/hash, file stability, native packet/valid-frame/priming/remainder metadata, finite bounded decoding and exact requested sample ranges. The initial `decodedPCMSHA256` stays immutable but is diagnostic under this contract: native Float32 output from identical AAC varied by up to **1.1920928955078125e-07**, crossing six PCM16 rounding boundaries in 16,000 samples. Neither implicit Int16 conversion nor explicit quantization made cross-read amplitude bits reliable. An absent contract keeps the older candidate's strict decoded-hash requirement; legacy single-file recordings are unaffected. No tolerance hash admits altered encoded files. Same-length decoder amplitude malfunction would no longer be an admission failure for the new contract, so signal quality, recognition and cross-OS decode acceptance remain explicit gates. Processing and App tests compare routed/sliced bytes against the actual admitted lease; separate native signal comparisons are quality tests.
 
Storage atomically stages bounded raw PCM and its predecessor plan before encoding or checking predecessor media. File receipts and manifests are synchronized before V32 registration. Registration atomically publishes raw pending work, immutable source lineage and normalized chunk/window/range references. Replay after first-pass retirement reuses the same identity; deleted identities cannot return. A typed proof of exact committed deletion permits clearing a leftover publication journal while retaining canonical AAC. Startup recovers one page of 16 journals; the joined periodic owner drains later pages while recording continues. Failed writes stop ingestion visibly and retain bounded accepted input for retry; queued upstream samples beyond the consumed prefix are not durably staged on that failure path. Disk failure before a successful durable write is not power-loss protection or gap-free failed-write recovery.
 
Native microphone/system delegates use CoreMedia presentation timestamps to detect continuity and integer output frames to timestamp resampled PCM. The initial wall-clock anchor is the first callback's receipt time, so absolute capture-time accuracy is still approximate. Callback jitter does not create artificial gaps. Real gaps, format changes, backwards/invalid timestamps and privacy resets change continuity identity. Already accepted converter tails are drained before physical/metadata boundaries; ambiguous failed-conversion or privacy tails remain excluded.
 
Live transcription, backfill and both refinement passes share the exact bounded reader and hold leases through guarded publication. Exact-media live and backfill explicitly require word timings through the retry policy; legacy live transcription retains its existing behavior. Word-start ownership is independent of processing order. Text without usable timing cannot replace overlapping context. This ownership rule does **not** establish that ASR recovers words cut by a chunk boundary: the authored native comparisons below fail recognition acceptance, and lookahead/recovery may still be needed.
 
Normal stop finishes native producers, cancels inference, then joins the App bridge and durable ingestion, including final partial chunks. A reported native stop error still follows this drain because Capture guarantees its local stream is finished before returning that error. Hard caller cancellation remains a separate path. Early stop before consumer registration is consumed once, and explicit preparation separates the next producer. Joined initialization rollback recreates closed media readers and reopens only quiescent internal owners; public terminal shutdown still rejects new initialization.
 
App playback resolves a committed immutable V30 transcript to its registered window, verifies native decoded media and revalidates current policy/SQLite state. UI plays a bounded in-memory WAV without creating a temporary audio file. Stop, cancelled loading, selection replacement, native completion and shutdown release the underlying file lease. App-owned policy changes revoke immediately; external SQLite deletion/revision changes are detected by 250 ms revalidation, not an atomic external-write/UI fence. Canonical transcript times have millisecond precision; playback allows only that known edge quantization while retaining exact manifest sample timing. New pending rows without a committed transcript do not receive an invented exact playback reference.
 
Physical cleanup of unreferenced chunk files is not scheduled: Database retains references/tombstones, and Storage's explicit authorized deletion operation revokes and joins readers before unlink. This source work makes no reclaimed-filesystem-space claim and does not remove existing history. The prior first-slice `verification.json` remains a historical receipt; it does not attest subsequent source edits.

Implementation:
 
- One App-owned one-second sampler reads native process CPU time, host ticks and physical footprint using monotonic intervals. CPU uses 100% per logical core; host use is separately normalized to all cores. Gaps, failed reads and clock/counter resets remain unknown. Bounded 1-/15-minute windows retain sampling coverage. Content-free minute delivery is bounded and joined before SQLite closes; resource rows expire after 30 days with a 43,200-row cap and bounded cleanup.
- The governor uses measured load: automatic fresh OCR pauses above 20% rolling app CPU during active use or 80% five-second host use. Recovery requires 15 continuous seconds below 15%/70%. This is an admission policy, not a guarantee that total CPU stays below 20%. Recording/writes/playback/search/dictation retain priority; explicit Process now still respects thermal/memory pressure. Historical transcription/OCR/model work waits for five quiet minutes and native background scheduling.
- Manual/current/historical OCR admission occurs before claiming SQLite work. At most three owned admission requests represent durable lanes; denied history stays pending while eligible fresh work proceeds. Governor cancellation releases the claim without consuming a failure retry; Vision checks cancellation between native requests, and a permit is retained until the request actually returns. Empty foreground probes preserve native scheduler grants. After three combined fresh-OCR/speech admissions, the oldest eligible nonpreferred request gets a turn; alternating preferred types cannot reset that fairness budget.

It accounts for screen video, audio, SQLite/journals, originals, indexes, models, caches, logs, backup/candidate copies, imported history and other files.
