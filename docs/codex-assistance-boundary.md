# Codex explicit-search prototype: integration blocked

The pinned public App Server cannot yet enforce Retrace's required exclusive three-tool surface. No broker, App Server session, authenticated request or model turn was started. This is a completed source/schema investigation, not runtime isolation acceptance.

## Exact unsupported boundary

The changelog's #45711 is an internal Rust extension control. That change introduced `AllowedTools`; in the actual 0.156.1 release source it is now `codex_extension_api::ToolPolicy.allowed_tools: Option<Vec<ToolName>>`. A host installs the policy in `ExtensionDataInit` before thread startup. The startup snapshot cannot be widened by later extension changes; a resumed thread needs a new supplied policy. Missing policy retains ordinary tools, an explicitly empty vector allows none, and names compare exactly with namespace identity (including the documented default-namespace equivalence). Generated Code Mode tools also require their own entries. This only narrows tools; it does not waive other permissions. [Original change](https://github.com/openai/codex/commit/2fdcdeaf0e219eea34c710e01de2ee0571ddeeb5), [pinned current type](https://github.com/openai/codex/blob/b412ff32c417f855c2b2d1581b77058eed87c84b/codex-rs/ext/extension-api/src/tool_policy.rs).

Public JSON-RPC cannot supply that value in this version. Both generated schema variants have `thread/start.dynamicTools`, but no tool-policy/allowlist/isolation field. The pinned config schema also has no matching setting. The current startup implementation constructs an empty `ExtensionDataInit`, optionally adds selected capability roots, and passes it alongside the dynamic tools. It never inserts `ToolPolicy` or `SessionIsolation`. Dynamic tools therefore add callable tools without establishing an exclusive catalog. [Pinned wire contract](https://github.com/openai/codex/blob/b412ff32c417f855c2b2d1581b77058eed87c84b/codex-rs/app-server-protocol/src/protocol/v2/thread.rs#L62), [startup implementation](https://github.com/openai/codex/blob/b412ff32c417f855c2b2d1581b77058eed87c84b/codex-rs/app-server/src/request_processors/thread_processor.rs#L1448).

Do not substitute invented `allowedTools` JSON, guessed config keys, prompting, a three-entry dynamic tool list, or `sandbox: read-only`. Rejecting unexpected *client-routed* tool requests cannot intercept every internally executed built-in. The safe boundary is to keep real evidence/model execution disabled until a pinned supported server accepts and enforces an exclusive startup policy, or an explicitly approved audited server extension supplies the internal policy. Rebuilding/forking Codex was not requested or performed.

## What the public protocol does support

The local stdio transport uses newline-delimited JSON-RPC. Initialization enables `capabilities.experimentalApi` for dynamic tools; then `initialized` completes the handshake. `thread/start` can include a namespace with three function schemas, for example `retrace.search`, `retrace.expand`, and `retrace.resolve`. Calls arrive through `item/tool/call` with thread, turn, call, namespace, tool and arguments. Replies use the request's JSON-RPC id and a typed `contentItems`/`success` result. This describes routing only, not exclusivity. [App Server documentation](https://developers.openai.com/codex/app-server#dynamic-tool-calls-experimental).

Cancellation uses `turn/interrupt` with exact thread/turn IDs. Its `{}` response acknowledges the request; the owning client must continue draining through the matching terminal turn event, cancel/join its own in-flight evidence reads, discard delayed responses and prevent post-cancel publication. Process shutdown is the last-resort bounded cleanup, not proof that earlier outputs were unsent. [Interrupt documentation](https://developers.openai.com/codex/app-server#interrupt-a-turn).

## Conditional minimum design after the control is available

1. Explicit user search only; no background activation. Create a fresh process and ephemeral thread for each bounded assistance session. Pin the native executable and generated protocol artifacts, validate the executable actually launched from an owned immutable bundle/private verified copy, and reject version/schema drift. Do not trust only a PATH result or the server's self-reported userAgent.
2. Require exactly the three namespaced read tools in the enforced startup policy, with all other built-in, hosted, MCP, app, Code Mode, delegation and discovery tools absent. `SessionIsolation.Isolated` is another internal extension control; public empty working directories and config overrides are not equivalent to it. The current source isolation policy strips inherited instruction providers/extensions and executor-discovered MCP sources. [Pinned isolation type](https://github.com/openai/codex/blob/b412ff32c417f855c2b2d1581b77058eed87c84b/codex-rs/ext/extension-api/src/session_isolation.rs).
3. Give the eventual process an app-owned private state directory and empty working directory; never attach the user's general CLI profile, repository roots, inherited provider URLs, MCP servers, skills, hooks, plug-ins or shell environment. Keep managed restrictions intact and fail closed if required isolation cannot be established. `ephemeral: true` limits thread persistence; `history.persistence = none` controls command history separately. Audit logs, SQLite state, crash reports and tool-result tracing independently; ephemeral is not a blanket no-disk guarantee. Set all exporters off and collect only categorical Retrace progress/latency. [Configuration reference](https://developers.openai.com/codex/config-reference).
4. Authentication needs an explicit app-owned lifecycle. The pinned config supports `cli_auth_credentials_store = ephemeral` for process-only credentials. Do not copy the user's CLI auth file or reuse its keyring state. External ChatGPT-token login is experimental and intended for hosts that already manage those tokens; Retrace does not yet have that lifecycle. Managed login/API-key paths remain separate future UI work, not an implicit grant from a search. No account endpoint was called here. [Auth documentation](https://developers.openai.com/codex/app-server#authentication-modes).
5. Freeze a disclosure grant containing request ID, user question, selected source-qualified evidence references/revisions, current policy/source stamps, expiry and strict aggregate byte/call budgets. `search` ranks only the admitted candidate set; `expand` follows exact bounded text spans/cursors; `resolve` returns availability and exact reference metadata. No file paths, arbitrary SQL, open-ended frame IDs, images/audio or unrelated history in the initial prototype. Existing `.agent` evidence reads currently deny disclosure; a broker must not bypass that by impersonating `.localUser`.
6. Treat every tool argument and model answer as untrusted. Validate namespace/function plus exact owner IDs and schemas, enforce bounded reads and current source/deletion/privacy checks before each reply, and bind final claims to refs/spans actually returned under the grant. Model text cannot enlarge the grant or authorize actions. Revalidate every support before presentation. Surface evidence gaps/contradictions; do not convert generated prose into a canonical fact.
7. Drive visible stages from actual events: Finding moments while local search runs, Checking evidence during bounded expansion/revalidation, Ready only after final admission. Cancel owns all child work and prevents late updates; partial results retain explicit incomplete status. Reduced-motion presentation remains App/UI work.

## Required future real-input gates

Before any real evidence request, a hermetic authored-data transport test must capture the *actual model-visible tool catalog* and execute adversarial absent/shell/MCP/web/exec/wait calls to prove only the three allowed functions can be advertised and dispatched. Test an empty allowlist, unknown names, namespace collisions, resume/restart, attempted policy replacement and changed binary/schema. Add actual filesystem tests for poisoned parent/home config, inherited plug-ins/hooks/AGENTS, no credential/history/log spill, and private-directory teardown. Exercise JSON-RPC bounds/duplicate IDs, interleaved calls, cancellation during SQLite reads and delayed output, source replacement, privacy change and deleted evidence. Provider/model execution, auth, latency, energy and installed acceptance have not been tested. Until exclusivity is enforceable, this integration remains disabled.
