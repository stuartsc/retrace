# Retrace recovery — 19 October 2026

## Accepted direction

Restore useful live transcription without starving capture or the foreground.
Search screen text, audio, app/window context and meaning from one field. Reuse
Outlook's known-speaker library and continuous-window processing on the spare
Mac, while keeping immediate text and exact search local. Separate recent work
from the wider FuseIntel business brief.

The root implementation owns coordination across Shared, App, Processing,
Database, Search and UI in this isolated checkout. No changes from another
checkout are reverted. Existing V24–V32 candidate work remains separate.

## Delivery sequence and acceptance

1. Fresh audio admission, cancellation, durable retry and measured CPU limits.
2. Local provisional/final transcription and explicit preparation health.
3. Exact metadata/audio search, semantic enrichment and exact navigation.
4. Revisioned remote speaker enrichment, corrections and failure recovery.
5. Connected/cached Brief, Signals and Ahead; bounded useful recent work.
6. Periodic storage accounting and reproducible quality/latency/resource checks.

Targets: provisional text p95 <=3 s, saved/searchable text <=15 s after utterance
end; exact fixture recall 100%, descriptive top-five recall >=90%; automatic
speaker-name precision >=98% on held-out examples; no wrong media navigation,
hidden capture gaps or lost pending work. Compare helper/system resource use,
not only app CPU; aim for 20% of one core average and >=50% reduction against the
reproduced overload, with foreground p95 within 10% of baseline. These are
acceptance targets, not results.

Each slice requires focused tests and review. Protocol changes require clean
debug validation and an independent clean optimized build. Installation and
rendered Live/Timeline acceptance must be recorded separately. Existing history,
power settings and rollback material remain protected.

  fresh Whisper uses one thread in Low Power Mode and two otherwise. Historical

### Native Whisper cancellation repair

despite the Swift token being wired correctly. Upstream v1.8.2 checked that
callback after encoding but did not install it on scheduled CPU graphs. The
versioned patch under `Vendors/whisper/patches/` forwards it into encoder,
decoder and automatic-language detection and clears borrowed callbacks after
joined synchronous native execution. The public header/ABI is unchanged.

Six native tests now pass, including model reuse after cancellation. English
joined in 0.007621 s and automatic-language detection in 0.062466 s. Returned
text, timed words and spans on both authored uncancelled regressions exactly
match the earlier unpatched run. Receipt:
`/tmp/retrace-recovery-native-whisper-final-backends.log`.
The first failed receipt is retained; a separate test run using freshly built
backend paths was interrupted and is not an acceptance result.

Only the patched Whisper library is promoted. The five retained ggml backends
match their committed source bytes; their installed code/data section hashes
also match (signing and load paths change whole-file hashes). Runtime inspection
confirmed the final tests loaded the retained vendored backends. C++ review

BLAS operations, Metal and external encoders are not made interruptible, and
this authored small-model test is not a worst-case bound for every model/input.

### Monitoring must not create load

An installed UI check found a separate regression: opening System Monitor starts
legacy process-log compaction and window loading against a 2.0 GB JSONL file.
Observed app RSS rose from roughly 0.8 GB before that check to over 8 GB while
the view was collecting its baseline. The reader/compactor materialized the
whole retained log and did not check cancellation. Returning to Dashboard did
not promptly stop that native file work. This observation was not a matched
benchmark and does not attribute all app load to the monitor.

The recovery reader now limits reads to the last 4 MiB, complete records to
128 KiB and the retained window to 256 samples. Automatic compaction is removed;
only the existing explicit Restart Baseline action can reset the log. File descriptors are owned, regular files are
checked without following symlinks, and cancelled work cannot publish an old
snapshot. The UI labels this a bounded recent sample rather than all 12 hours.
The old diagnostic file remains in place. Real sparse-file, boundary and
cancellation regressions are under `UI/Tests/ProcessCPULogReaderTests.swift`,
including cancellation after opening the native descriptor and after a first
decoded sampler row, then a complete retry. The final clean debug/optimized
validation above follows the changed private actor method signatures.
After that clean pass, the cancellation test's oracle was strengthened to check
the authored process's exact 0.02 CPU seconds, so unrelated live sample duration
cannot hide a missing row. All nine focused tests pass again in
`/tmp/retrace-recovery-final-reader-oracle.log`; product inputs remain unchanged.
