## Implementation and review details

- Activity collection is a separate, initially disabled control, gated by the existing master recording permission/pause state. App activation is stored before bounded window/document enrichment; later enrichment starts at its actual observation time. Screenshot failure does not silently turn off the independent activity stream. Observer loss, exclusion, overflow and persistence recovery have explicit coverage/health states.
- The additive V21 migration provides durable activity/feed/checkpoints, confirmed correction receipts, a native/imported store registry, immutable extraction snapshots, validated activity-to-screen links and search revision fences. Compatibility OCR writers also append snapshots transactionally; flat legacy text does not receive unsupported geometric highlights. Imported databases remain read-only.
- The timeline offers episodes, retained intervals and exact evidence. Grouping/hiding changes presentation only. Selected corrections do not spill into adjacent or future observations; unacknowledged corrections stay visibly pending. Metadata search does not require OCR or a model download. Direct screen search is independent of episode labels.
- Exact references preserve source, store, observation, frame and extraction revision. Encoded samples and journal records are verified before disclosure. Current source/privacy/deletion state is checked again after asynchronous reads; a stale result cannot silently use another store or newer text. Missing images can expose the retained cited text with a separate unavailable-image state. Agent disclosure currently fails closed; no new external agent access was enabled.
- URL metadata drops query/fragment/userinfo and unsafe opaque path components before new capture sinks. The raw navigation value is reduced to a local identity hash so scrubbed URLs do not merge separate contexts. This is a tested conservative policy, not a claim to recognize every possible secret.
- Independent review found and prompted regressions/fixes for stale source selections, delayed timeline projection, removed activity associations, correction scope, startup/pause races and capture writer finalization. Source-qualified thumbnails are included in the same disclosure boundary as exact selection.

### Implementation boundary

V23 adds a singleton native policy/session fence, a conservative metadata epoch and bounded claim/artifact storage. A fresh live database actor capability is required in addition to persisted active state. Capture serializes policy preparation, configuration application, activation and exact-token rollback; ordinary recording pause retains historical authority, while owning-service shutdown ends it. Root coordinated Shared/App contracts, Database and Capture module owners, and a separate read-only reviewer.

Claims bind native feed/store identity, exact observation/revision/block/page scope, consumer lease, source sequence, metadata epoch, writer/policy incarnation, declared transformation and a hash of the actual retained input. At most one live attempt exists per consumer/observation/channel. Retained source payloads are immutable; metadata changes invalidate held work even after an A→B→A transition. Deletion removes staged bytes in the source transaction. Revocation changes constant-size state rather than rewriting historical rows.

The result is **opaque, staged and unpublished**. A checksum and receipt establish atomic byte storage, not semantic correctness. Both V22 channels remain blocked. Limits are 256 attempts/receipts, 256 KiB per artifact, 16 MiB aggregate artifact bytes, 64 KiB encoded policy/claim/receipt records, an 8 MiB retained snapshot read ceiling, and at most 100 cleanup rows per call. Execution attempts are at most 30 seconds using wall and monotonic clocks; completed results remain readable/retryable for at most 24 hours only while their consumer and all current fences still hold. This is not a physical COMMIT/fsync-time deadline guarantee.

App's local-only endpoints deny agent callers before writer or metric access. The policy bridge and artifact endpoints emit categorical `progressive_recall_action` metrics without source text, references or identifiers. Exact retained presentation uses the same privacy predicate. Service initialization coalesces callers and installs the policy before other services; cancellation/shutdown joins partial acquisition and cleanup. Startup rollback and shutdown preserve both error domains rather than swallowing one.
