# Retrace Live: context, spoken markers and complete MCP access

## 1. Redesign Live around useful context

Remove Operating Brief, Brief/Signals/Ahead, its dedicated polling, cache, settings and connection UI. Preserve Outlook’s shared intelligence services and voice library.

Use the agreed **60/40 resizable transcript-and-screen layout**, with tabs below 900 points. Remove aggregate statistics from Live and retain a compact recording, transcription, speaker-processing and connectivity status strip.

- Show newest-first speaker turns, exact-range playback and saved recordings awaiting text. Load older history automatically as the user scrolls down; optional date filters apply to explicit searches.
- Selecting speech shows screen captures from that interval, application/window names and readable OCR. Missing coverage remains explicit.
- Keep foreground-window attribution distinct from proven ownership of individual OCR regions.
- Preserve reading position; provide “Return to live”.
- Search the selected time range across transcripts, speakers, OCR, application/window titles, notes and markers, with pagination.
- Provide **Mark now**, **Voice markers → Settings**, a searchable marker list and **Copy context** directly from Live.

Copy context includes selected material, speaker status, source references, timestamps and coverage. It previews what will be copied and accepts an optional question for the receiving assistant.

## 2. Configurable spoken markers with quick feedback

Add **Settings → Voice markers**. Each rule has a name, trigger phrase/aliases, intended meaning, predefined action and enabled state.

Example:

| Field | Value |
|---|---|
| Name | Remember this context |
| Keyword phrase | Purple banana |
| Intended meaning | Preserve this moment and the relevant explanation |
| Action | Mark on timeline |

The first supported action is **Mark on timeline**. Use a typed action registry for future actions; free-text descriptions cannot execute arbitrary commands.

**Detection and timing**

- Trigger from **microphone speech**, as selected. System-audio transcripts and OCR cannot activate rules. Speaker identification enriches the marker without delaying it.
- Use an on-device streaming SpeechAnalyzer path for quick recognition and audio timing, extending the existing batch adapter. Apple supports streaming provisional/final results and timed text. [Apple’s SpeechAnalyzer documentation](https://developer.apple.com/videos/play/wwdc2025/277/)
- Share the existing microphone capture through a bounded secondary subscription. Never open another microphone session or add a competing iterator to the recording stream.
- Match complete configured phrases with case/punctuation normalization and explicit aliases. Semantic similarity alone must not trigger actions.
- Store the phrase’s **start and end in the original audio timeline**, separately from detection and save times. Preserve timing uncertainty; do not invent precise boundaries from a whole-sentence timestamp.
- Save a durable provisional marker before showing “Keyword heard”; confirm it when recognition/alignment settles. Keep provisional and confirmed states distinguishable.
- Deduplicate overlapping batches, partial/final revisions and retry delivery. Two genuinely separate utterances produce two markers.
- Provide a subtle visual acknowledgement and an optional chime. Include Undo and a manual marker fallback. Prevent Retrace’s own playback from retriggering its markers.
- Keep recording independent of recognition failures. Disabled rules stop the listener; unavailable assets, dropped input or resource pressure produce a visible degraded state.

**Acceptance target:** acknowledgement p95 within three seconds of phrase completion on this Mac. Delayed recognition may recover a correctly timed marker, but does not count as meeting that target.

## 3. Flexible context around an immutable anchor

**No fixed before/after duration defines the marker’s context.** The phrase span is the durable anchor; context is a separately versioned interpretation.

- A marker can reference a short surrounding passage, ten minutes earlier, several minutes afterward, or multiple relevant intervals.
- Continuously associate the explanation following the phrase. Use the configured meaning, spoken references, conversation continuity and application/document changes to identify relevant material.
- Run bounded semantic retrieval on the spare Mac using its existing local embedding/reranking infrastructure. Expand backward and forward through paginated evidence; silence is a clue, not an automatic boundary.
- Present proposed ranges, their supporting material and whether context is still developing or incomplete. New transcription can improve the proposal.
- Let Stuart or an authorized MCP client expand, trim, replace or pin those ranges. Subsequent automatic analysis must preserve manual corrections.
- Retain the verbatim explanation separately from any suggested title or task description. A spoken task becomes documented context, not an automatically executed instruction.
- Markers work without screenshots and remain navigable in timeline/calendar views containing audio-only moments.

Use a separate versioned context database for rules, markers, annotations, corrections and delivery state, preserving compatibility with the installed V23 recording library. References identify the source store, recording generation, media range and revision; marker creation does not duplicate recordings.

Connect the existing spare-Mac speaker worker through durable publication, transport, acknowledgements and result import. Prioritise fresh work, prevent duplicate inference and preserve first-pass text. Automatically apply known names only after held-out matching meets the existing 98% precision target; otherwise show distinct anonymous speakers and clearly labelled name suggestions.

## 4. MCP access to native Retrace capabilities

Introduce a dedicated private **Retrace MCP endpoint** at `/retrace-mcp`, with its primary-host listener on loopback port 9012 behind the existing private transport. Preserve Outlook’s existing read-only MCP contract.

Expose a capability manifest and typed operations covering:

| Area | MCP functionality |
|---|---|
| Retrieval | Search, timeline ranges, screenshots, OCR, transcripts, speaker turns, exact references and context |
| Markers | Create/list/search/update/remove markers; retrieve phrase spans and explanations; revise or pin context |
| Rules and annotations | Manage keyword rules, tags, comments and speaker corrections |
| Native navigation | Open exact timeline items and control playback through explicit foreground actions |
| Recording and settings | Read/control recording, supported capture/audio settings and source configuration |
| Processing | Request OCR/transcription repair, processing overrides and supported index work; inspect/cancel jobs |
| Operations | Read health, backlog, CPU/storage reports and usage; invoke supported import, maintenance and retention operations |
| Sharing | Retrieve/copy supported text and media selections with source identity and coverage |

Only expose implemented functionality. Existing “coming soon” features remain unavailable.

- UI and MCP call the same App-owned services and validations. MCP receives no arbitrary SQL, filesystem or shell execution interface.
- Use per-client capability grants. Destructive operations require a concrete preview and explicit confirmation bound to that preview.
- Commands carry request IDs, revision checks and durable outcomes so retries cannot repeat actions. Long operations return job IDs with progress/cancellation.
- Offline reads disclose freshness. Commands requiring the laptop return unavailable rather than silently executing later.
- Add shared `KeywordRule`, `TimelineMarker`, context-range/proposal and command/result contracts. UI, Copy context and MCP consume the same corrected records.
- Preserve existing exclusions, imported-source restrictions and OS permission boundaries. Recorded text remains quoted evidence, not tool instructions.
