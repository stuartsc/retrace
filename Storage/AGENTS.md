# STORAGE Agent Instructions

Storage owns local media I/O, HEVC segment writing, raw screenshot WAL recovery, audio segment files and storage health. Depend on `Shared` protocols and models; database publication remains behind `DatabaseProtocol`.

**Status:** HEVC encoding uses AVAssetWriter/VideoToolbox, interframe compression, default GOP 30, and a synthetic 30 fps encoded timebase. Audio is stored as AAC `.m4a` (16 kHz mono). Encryption is not currently implemented in this module. Performance and monthly storage targets are targets, not measured guarantees.

The storage root is configurable through `AppPaths`. Screen video lives under `chunks/YYYYMM/DD/{timestampID}` (extensionless MP4). New originals live under `wal/original_segment_{timestampID}/`, a namespace older rollback binaries do not enumerate; legacy `wal/active_segment_{timestampID}/` remains readable. The timestamp-based path ID is distinct from the database `video.id`. Never substitute one for the other.

Strict encoded-frame reads retry a stale image generator once, then reject a timestamp mismatch instead of returning a neighboring capture. Explicitly tolerant playback remains available. `StorageManagerTests` covers this with a real HEVC timestamp gap.

Exact screen evidence uses `ExactFrameReader` and `WALManager.readExactFrame`. Encoded reads create fresh image generators, validate finite sample timestamps and expected dimensions, check source-file stability, and propagate cancellation. WAL evidence requires a conflict-free database frame ID map and a validated record boundary; capture index is never a fallback. Timestamp tolerance is at most the native database's one millisecond precision. The dedicated exact-media tests encode real HEVC samples and write real binary WAL records; these fixtures do not establish installed-app latency.

The root-coordinated `StorageProtocol.readFrameForProcessing` method reads native archived frames into BGRA without an intermediate JPEG. It requires matching video identity, an in-range frame index, exact dimensions/timestamp and a relative path resolving inside the storage root, including symlink validation. `FrameConverter.createCapturedFrame` checks arithmetic/stride allocation and preserves saved timestamp/metadata. Presentation image APIs remain separate. Real HEVC tests cover decoded pixel identity through the queue and mismatched identity, traversal and escaping symlinks. Archive codec/quality settings remain separate from original retention.

`configureOriginalStore` binds new captures to the database UUID before the first pixels are admitted. `readOriginalFrameForProcessing` locates original pixels by this source UUID and persisted frame identity across recovery archive remapping. It verifies timestamp, dimensions and captured display identity; unknown display identity is not a wildcard. `original-retention.json` durably records source UUID, sealing, archive mappings and deletion fences. Finalizing or cancelling a writer closes ownership but retains already-written originals. `confirmOriginalArchive` requires the database-qualified video identity after publication and verifies every decoded archive sample. Reconciliation removes only sealed sessions whose frames have matching durable extraction/archive acknowledgements or explicit deletion from the same database, after all raw readers finish. Pending, failed, unmapped, unattributed legacy and damaged originals remain retained. The 5 GiB ceiling and 20 GiB free-space headroom reject new pixels before append; pressure never evicts pending originals. Capture, map, metadata and acknowledgement writes are synchronized to disk.

## Recovery invariants

- Normal capture writes `frames.bin` and `metadata.json`; `frame_id_map.bin` records exact database frame ID to byte offset mappings.
- New records use a 76-byte V2 header, a required complete `FrameMetadata` JSON payload capped at 64 KiB, and raw pixels. A reserved non-finite marker distinguishes V2 from valid V1 timestamps. Version/reserved bits, dimensions/stride, metadata SHA256 and matching display identity are checked before pixels are returned. Optional capture-policy digests must be 64 lowercase hexadecimal characters. Invalid V2 never downgrades to legacy metadata. All normal, indexed, exact and recovery readers use the same codec; V1 and mixed-version records remain readable with genuinely absent fields left nil. Admission includes the complete serialized record plus acknowledgement reserves before any write.
- Recovery scans headers and metadata without loading pixel payloads. Encoding reads one validated frame at a time; each output chunk holds at most 150 metadata descriptors. Individual raw frames have a 256 MiB allocation limit (including supported 8K BGRA); unsupported or corrupt input is retained.
- Sessions created by the current WALManager belong to live capture and are excluded from `listRecoverableSessions`; `listActiveSessions` remains inclusive for orphan bookkeeping.
- `isLiveSession` reports current-manager ownership, not filesystem presence. Retained incomplete journals must not be mistaken for writers that will append more pixels.
- Recent or old WAL files above 512 MiB are recoverable; size and age alone must never trigger quarantine or deletion.
- `recovery-progress.json` records output identity before encoding, finalized video metadata before database publication, and completion after atomic database commit and successful OCR enqueue. File and directory synchronization persist journal transitions.
- Recovery persists exact source frame-ID mappings and archive receipts before source reconciliation. Complete archive receipts prevent retained originals from being re-encoded on restart. Enqueue success does not acknowledge extraction or permit cleanup. A missing previously mapped database frame is durably fenced as deleted; it must never be inserted as new history.
- When deletion changes a checkpointed chunk, recovery creates a fresh survivor-only archive and preserves the previous potentially published output. The database's immutable source aliases authorize the survivor remap and reject deletion again inside the publication transaction.
- Recovery uses the video-only `createRecoverySegmentWriter()` path. Creating a second raw WAL would cause duplicate recovery after a crash; the original WAL already supplies durability.
- Database publication uses `commitRecoveredFrames`: stable mapped frame IDs, original video path plus frame index, and output video path plus frame index make retry idempotent. Never use second-resolution timestamps to identify frames.
- Partial encoding, corrupt/truncated tails, missing output, failed publication, and failed enqueue retain the source WAL. Complete valid prefixes can be published without deleting a damaged tail. Registration and individual reads validate the preceding records and requested target, then stop; they must not require a later damaged tail to parse. Full-session reads still reject malformed tails. Recovery tests require prefix OCR enqueue, exact mapped originals and durable archive receipts across restart, not merely a committed database row.
- The caller that creates coalesced recovery owns its cancellation; passive joiners must not cancel that shared work. Check cancellation before publication, after enqueue before the committed checkpoint, and before source cleanup, including when an enqueue callback consumes cancellation. Retain the WAL and verified output for idempotent retry.
- Do not delete source files or claim success until all encoded output and database mappings are confirmed. Legacy quarantine pruning never removes the new original namespace or a directory carrying a retention receipt; these bytes remain part of spool admission. Recovery and archive confirmation hold reader leases until their source reads finish. No production files are touched by unit/integration tests.

## Coding and validation

Use async/await and actors for I/O. Keep filesystem, SQLite, decoding and encoding work off the main/UI actor. Log user/action-scoped recovery progress with `Log` and `.storage`; never log screenshot pixels or extracted private content. New user actions require daily metrics under root instructions; this recovery change repairs an existing startup action.

Tests must use real binary WAL files, FileManager, SQLite and media encoding, including a valid sparse WAL above 512 MiB, corrupt/truncated tails, exact identity mapping and interrupted/retried publication. `OriginalFrameSpoolTests` covers durable blank extraction, independent archive acknowledgement, remapped recovery, reader completion across manager instances, archive damage, pre-write pressure rejection and deletion across restart. Run focused checks with `RETRACE_TEST_DISABLE_FILE_LOGGING=1 swift test --jobs 1 -Xswiftc -j1 --filter 'OriginalFrameSpoolTests|WALRecoveryTests|ExactWALFrameTests'`, coordinating SwiftPM access with other agents. StorageTests also links Database for real integration checks; production Storage depends only on Shared. These source regressions do not establish installed performance, physical power-loss behavior or local-trial acceptance.

`WALFrameCodecTests` writes actual V1/V2 binary records, restarts readers before database registration, checks complete capture policy/context retention across every reader, rejects malformed metadata/version/checksum/display identity, and verifies metadata-aware pressure admission. Include this suite in the focused Storage validation after changes to the record format.

Spool lookup attributes integrity failures only after proving the requested store UUID and a persisted frame ID. An unrelated or unattributable corrupt session stays retained and does not block other frames' verified archive reads. Corruption in a proved candidate still fails closed, including ambiguous candidates.

Only edit Storage unless an explicit cross-module assignment authorizes a narrow protocol change. Keep this file current when files or recovery semantics change.

`StorageUsageMonitor` implements the root-coordinated `StorageUsageReportingProtocol` independently of `StorageManager` and capture's writer actor. Its constructor and `snapshot()` are inert; `start()` awaits one scan and starts a fifteen-minute loop, so the App owner must start it from an owned background task. Concurrent `refresh()` calls join a detached background scan; cancelling a waiter does not revoke shared work. Terminal `close()` cancels and joins the scan and periodic loop. Reports retain both the latest attempt and the last complete observation, with explicit unavailable/partial/cancelled roots and bounded categorical errors. Never present an inaccessible root as zero or a prior complete observation as current.

The scanner uses descriptor-relative `openat`/`fstatat`/`readdir`, never shell `du`, payload reads or a view-body filesystem scan. Ancestors must be real directories; an exact leaf root may also be a regular file. File leaves use nonblocking, no-follow, metadata-only opens and verify identity/type after opening, so a concurrent FIFO substitution cannot block awaiting a writer. Root/ancestor symlinks and dot traversal are rejected, descendant symlinks are counted as skipped and never followed. Foundation rewrites canonical `/private/var` to the `/var` symlink when standardizing URLs, so the scanner deliberately preserves supplied components. Most-specific configured roots own overlapping content; exact duplicate roots and device/inode hard links are counted once. Iteration is bounded by directory depth, linked inode count, volume count, issue count and root count; ordinary file count does not grow an in-memory manifest. Scans yield in batches, slowing under a prompt cached-pressure callback. Native filesystem calls themselves are not interruptible, and the filesystem is observed over an interval, not atomically frozen.

Usage separates logical regular-file bytes, allocated blocks and volume free space. APFS clone allocation is not uniquely occupied or reclaimable space. Optional missing leaf roots are known-zero only when their direct parent can be opened; missing required roots or unavailable parents remain unavailable. Native classification includes screen chunks, AAC, SQLite and journal siblings, original WAL/hidden originals/audio publication journals, indexes, models, caches/temp and logs. Explicit backup, candidate and imported roots retain their own default category. Regular-file accounting excludes directory metadata, sockets and symlink targets. The private-files regressions cover category totals, sparse allocation, hard links, overlapping roots, root/ancestor/child symlinks, permission denial, missing volumes/parents, bounded errors, refresh coalescing, passive cancellation, joined close, periodic scheduling and more than 10,000 files. No test enumerates live libraries or changes global preferences; App owns content-free daily metric publication.

`WALFrameCompressionTests` compares disabled/raw, native LZFSE and LZ4 on independently decoded records, including CoreGraphics/CoreText-rendered coloured text and changed digits, nonzero row padding, raw fallback, pixel checksums, mixed-version seek offsets and malformed/truncated payloads. V3 is an independently switchable source candidate through `StorageConfig.originalPixelCompression` (`disabled`, `lzfse`, `lz4`), forwarded by `StorageManager.initialize` to the actual WAL writer. Default and absent legacy configuration remain disabled/V2; no UserDefaults are read by Storage. Changing `WALManager.configureOriginalPixelCompression` affects subsequent records without rewriting earlier V1/V2/V3 records or changing HEVC archive configuration. The V3 148-byte header extends V2 with stored length, codec/reserved identifiers and independent SHA256 hashes of stored payload and every original pixel byte. Metadata scans check bounds without decompressing; pixel reads require exact output length, stream termination, no reported unused encoded bytes and matching stored/restored SHA256 hashes. Native decoders may consume trailing input, so the stored-payload hash is independently required. Authored smoke measurements report process CPU seconds, wall time and stored bytes, including native encode/write/read/decode; these three small text screens do not satisfy representative corpus savings/latency acceptance or promote a codec. No historical recompression occurs.

`WALWriterCompressionTests` covers configuration decoding, real `StorageManager`/`IncrementalSegmentWriter` forwarding, restart and exact mapped reads, mixed V2/V3 seek offsets, raw fallback tampering, preserved pending originals, encoded-byte pressure/headroom including acknowledgement reserves, cancellation and actual file/directory write denial. Compression remains bounded by the codec's 256 MiB original-frame limit and uses raw fallback if compression fails or expands. Admission accounts for the complete stored record after bounded encoding. Append publishes in-memory metadata only after synchronized pixels and metadata succeed; a failed append restores prior metadata and truncates back to the previous byte boundary. If rollback itself cannot complete, the source stays retained and that manager rejects further appends to the session pending recovery. Extraction/archive/reader-release requirements remain unchanged.

`HEVCEncoder.accelerationStatus()` reports hardware inventory, explicit selection and fallback permission separately. AVAssetWriter does not expose its underlying VTSession, so actual hardware use remains unverified; an available hardware encoder is not proof of use, and fallback permission is not proof of software use. Default `.automatic` emits the original settings. Opt-in `.preferHardware`, `.requireHardware` and `.softwareOnly` use supported VideoToolbox keys beneath top-level `AVVideoEncoderSpecificationKey`; required hardware is never silently retried in software. The old boolean is deprecated and conservatively false when unverified. `HEVCEncoderTests` includes real prefer-hardware encode/decode with exact sample time, explicit selection dictionaries and status reset.

`AudioChunkMediaStore` is the independently gated source candidate for non-overlapping, at-most-ten-second AAC chunks. Capture supplies fixed 16 kHz mono Int16 and immutable stream/sample identities; windows add at most five seconds from the immediately preceding chunk using ordered integer ranges. The store writes the bounded raw PCM plus complete predecessor plan as one synchronized immutable publication journal before encoding. Native packet-table valid/priming/remainder counts, packet arithmetic, asset timing and encoded SHA256 are verified before the chunk receipt and media become visible. New receipts explicitly record `decodeContract: nativeAACPCM16V1`; their `decodedPCMSHA256` records the encode-time native verification output as a diagnostic, not a promise of identical lossy decoder output on later reads. An absent contract retains the pretrial strict decoded-hash requirement. The receipt precedes the encoded target, making restart recovery finish the same verified file instead of attesting an unrelated pre-existing file. Dedicated `audio/chunk-media/pending/` journals remain until canonical database publication is acknowledged; acknowledgement rechecks media before removing the raw retry source. Old AAC batches are unchanged.

New media reads validate canonical paths, bounded manifest/file sizes, exact encoded hashes, packet timing and exactly decoded frame counts. The candidate decodes to native Float32 and explicitly quantizes finite samples to clipped little-endian Int16 using nearest rounding with ties away from zero. Direct native-buffer diagnostics found Float32 variation up to 1.1920928955078125e-07 when reopening identical AAC, crossing six Int16 rounding boundaries in 16,000 samples; explicit quantization did not eliminate it. The versioned contract does not tolerance-hash PCM or admit changed encoded bytes. Process-global leases coordinate separate playback/writer instances. Authorized deletion writes durable identity tombstones, revokes selected leases, joins consumer release and only then unlinks; a restart cannot revive deleted journals. Close revokes and joins owned consumers and entered operations; consumers must release revoked leases. `AudioChunkMediaStoreTests` uses actual native AAC, authored speech across the ten-second boundary, exact shared range identities/offsets/counts, a separate test-only sample-quality comparison, repeated reopening on several task priorities, explicit strict legacy/diagnostic new receipt behavior, interrupted filesystem publication/restart, concurrent replay, tampering, symlinks and joined deletion. These source tests do not promote codec settings or establish installed storage/performance acceptance.
